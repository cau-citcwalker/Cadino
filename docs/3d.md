# 3D modelling

> **Last updated:** 2026-10-15 · **Status:** in progress

How CAD-rhino adds Rhino-style solid modelling to the CADCraft 2D core without rewriting it.

## Principles

- **The 2D pipeline stays.** Display lists, picking, snaps and the GPU canvas keep working in 2D.
  An orthographic view maps the WCS XY plane (z = 0) to the screen with a 2D affine transform,
  so a rotated view of 2D content is the top-level `Mat3` of the render context.
- **The document stays kernel-free.** `doc` stores a solid as data: the B-rep in OpenCASCADE's
  text format, a cached tessellation and a transform. Moving, rotating, scaling and copying a
  solid only changes its transform, so every existing modify command works on solids. The
  kernel is needed only to make or combine shapes.
- **One kernel crate.** `cadcraft-kernel` (L0) wraps `opencascade` behind the `occt` feature.
  Without it (the web build) the kernel returns "not available" and drawings still show the
  stored meshes.

## Pieces

| Layer | Crate | What |
|---|---|---|
| L0 | `geom` | `Mesh3` (vertices, triangles, edge polylines), `ViewDir` (view direction → rotation, the XY-plane `Mat3`) |
| L0 | `kernel` | Primitives, extrude, revolve, booleans, fillet, tessellation, B-rep text and STEP/STL I/O |
| L1 | `doc` | `EntityKind::Solid3d { brep, mesh, xform }` |
| L2 | `render` | Solid edges (wireframe) and depth-sorted shaded faces, projected by the view |
| L3 | `io` | DXF: `3DSOLID` carrying our B-rep in CAD-rhino xdata (AutoCAD's ACIS data is not written) |
| L4 | `engine` | BOX, CYLINDER, SPHERE, CONE, TORUS, EXTRUDE, REVOLVE, UNION/SUBTRACT/INTERSECT on solids, FILLETEDGE, VPOINT, PLAN, view presets, VSCURRENT, STEP/STL import and export |
| L5 | `ui-egui` | `Xf` carries the view projection; orbit drag; ViewCube faces |

## Commands

| Command | JSON form |
|---|---|
| BOX | `{corner1: [x,y,z?], corner2: [x,y,z?], height?}` or `{corner1, length, width, height}` |
| CYLINDER, CONE | `{center, radius, height}` (CONE: `topRadius?`) |
| SPHERE | `{center, radius}` |
| TORUS | `{center, radius, tube}` |
| EXTRUDE | `{handles?, height}`: closed polylines, circles, single-loop regions (erased) |
| REVOLVE | `{handles?, axis: [[x,y],[x,y]], angle?}` (degrees, default 360) |
| FILLETEDGE | `{handles?, radius}`: rounds every edge |
| UNION, SUBTRACT, INTERSECT | as for regions; solids go to the kernel |
| STEPOUT, STLOUT, STEPIN | `{path, handles?}` |
| VPOINT | `{direction: [x,y,z]}`, `{azimuth, elevation}` or `{preset}` |
| PLAN, `view.top` … `view.nwiso` | preset views |
| 3DORBIT | `{azimuth?, elevation?}`; on the canvas Shift+middle drag, or drag the ViewCube ring |
| VSCURRENT | `{style: 2dwireframe \| shaded …}` |

## Building with the kernel (Windows, MSVC)

The desktop app and the CLI enable `cadcraft-kernel/occt` on native targets; the first build
compiles OpenCASCADE 7.8.1 from source into `target/OCCT` (about 20–30 minutes).

1. CMake: Visual Studio's own works. Point `CMAKE` at it, for example
   `C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe`.
   `.cargo/config.toml` sets `CMAKE_POLICY_VERSION_MINIMUM=3.5` for CMake 4.
2. Run `scripts/occt-msvc-setup.ps1` once before the first build and again after OCCT is
   rebuilt: it adds the `opencascade-sys` junction cxx-build needs without Developer Mode, and
   makes OCCT's `Handle_X` a typedef on MSVC as the bindings expect.
3. `cargo test -p cadcraft-engine --features occt` runs the modelling tests.

## Known ceilings

- Picking in a rotated view goes through the XY plane; elevated solid faces pick by footprint.
- 2D entities with elevation or thickness draw at z = 0 in rotated views.
- Shaded faces are painter-sorted per solid, not depth-buffered: interpenetrating solids can
  draw in the wrong order.
- OpenCASCADE runs in-process. A C++ exception it doesn't catch ends the process.
